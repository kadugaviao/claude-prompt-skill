## Resposta final

**Tipo:** Refatoração / migração de código · **Modo sugerido:** plan mode · **Raciocínio:** normal

```text
Objetivo: migre todos os testes do projeto `loja` de JUnit 4 para JUnit 5 (Jupiter) e remova as dependências do JUnit 4. Quero que a suíte rode só na plataforma JUnit 5, sem o motor vintage, sem mudar o que cada teste verifica.

Contexto:
- Spring Boot 3.3.5, Java 21, Maven (`./mvnw`). Camadas: controller -> service -> repository.
- O `spring-boot-starter-test` já traz JUnit Jupiter, Mockito e AssertJ.
- O `pom.xml` declara hoje `junit:junit:4.13.2` e `org.junit.vintage:junit-vintage-engine`, ambos com escopo test. Os dois existem só para manter testes JUnit 4 rodando.
- Hoje só existe um teste: `src/test/java/com/exemplo/loja/service/PedidoServiceTest.java`. Ele usa `@Before`, `@Test(expected = NoSuchElementException.class)`, `org.junit.Assert.*` e mocks criados à mão com `mock(...)`.

Tarefa:
1. Procure em `src/test` qualquer uso de JUnit 4, além do arquivo acima: `org.junit.` fora de `org.junit.jupiter`, `@RunWith`, `@Rule`, `@ClassRule`, `@Ignore`, `@BeforeClass`/`@AfterClass` e `Assume`. Liste o que encontrar antes de editar.
2. Em cada teste, troque os imports para `org.junit.jupiter.api.*`. Converta `@Before`/`@After` em `@BeforeEach`/`@AfterEach`, `@BeforeClass`/`@AfterClass` em `@BeforeAll`/`@AfterAll` e `@Ignore` em `@Disabled`. Troque `@Test(expected = X.class)` por `assertThrows(X.class, () -> ...)`. Use `org.junit.jupiter.api.Assertions`. Se algum teste passar mensagem nas asserções, ela vai para o último argumento. Classes e métodos de teste podem ficar package-private.
3. Se aparecer `@RunWith(MockitoJUnitRunner.class)`, troque por `@ExtendWith(MockitoExtension.class)`. Se aparecer `@RunWith(SpringRunner.class)`, remova, porque `@SpringBootTest` e os outros test slices já registram a extensão do Spring. Para `@Rule`, use o equivalente do Jupiter (`@TempDir`, `assertThrows` etc.). Se não houver equivalente direto, pare e me diga antes de improvisar.
4. Remova `junit:junit` e `junit-vintage-engine` do `pom.xml`. Não adicione `junit-jupiter` com versão explícita, porque o parent do Spring Boot já gerencia essa versão.
5. Rode `./mvnw test`.

Restrições:
- Mantenha a lógica e a cobertura de cada teste: mesmos cenários, mesmas asserções, mesmos nomes de método. O objetivo é trocar o framework, não reescrever os testes.
- Não altere nada em `src/main`. Se algum teste só passar com mudança no código de produção, pare e me explique, porque isso indica um problema que não é desta migração.
- Não troque as asserções do JUnit por AssertJ e não converta os mocks manuais em `@Mock`/`@InjectMocks`. São melhorias de estilo fora deste escopo. Se achar que valem a pena, sugira em uma frase no final.
- Não faça commit nem push.

Pronto quando:
- `./mvnw test` termina com BUILD SUCCESS e o número de testes executados é o mesmo de antes da migração (rode uma vez antes para ter a contagem).
- `grep -rnE "import (static )?org\.junit\.(Test|Before|After|Assert|Ignore|Rule|runner|BeforeClass|AfterClass|Assume)" src/test` não retorna nada.
- `./mvnw dependency:tree -Dscope=test` não mostra `junit:junit` nem `junit-vintage-engine`.

Formato da resposta:
- Arquivos alterados, cada um com uma linha sobre o que mudou.
- Diff do `pom.xml`.
- Saída do `./mvnw test` (linha `Tests run:` e resultado) antes e depois, e a saída dos dois comandos de verificação.
- Pendências ou casos sem equivalente direto, se houver.
```
