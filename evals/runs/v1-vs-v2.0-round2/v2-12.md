## Contexto
Projeto Maven `loja`: Spring Boot 3.3.5 e Java 21. O `spring-boot-starter-test` já inclui JUnit Jupiter 5.10.x e Mockito 5. Hoje o `pom.xml` também declara `junit:junit:4.13.2` e `org.junit.vintage:junit-vintage-engine`, que existem só para rodar os testes antigos.

## Insumos

- `pom.xml`
- `src/test/java/com/exemplo/loja/service/PedidoServiceTest.java` (é o único teste hoje; usa `@Before`, `@Test(expected = java.util.NoSuchElementException.class)` e `import static org.junit.Assert.*`)

## Tarefa e escopo
1. Rode `grep -rn "org.junit" src/test` para achar tudo o que usa JUnit 4. Se aparecerem arquivos além do `PedidoServiceTest.java`, migre todos.
2. Em cada teste:
   - Troque `org.junit.Test` por `org.junit.jupiter.api.Test`.
   - Troque `@Before`/`@After` por `@BeforeEach`/`@AfterEach` e `@BeforeClass`/`@AfterClass` por `@BeforeAll`/`@AfterAll`.
   - Troque `org.junit.Assert` por `org.junit.jupiter.api.Assertions`. Se alguma asserção recebia mensagem como primeiro parâmetro, passe a mensagem para o último.
   - Substitua `@Test(expected = X.class)` por `assertThrows(X.class, () -> ...)`.
   - Se aparecer `@Ignore`, troque por `@Disabled`. `@RunWith(MockitoJUnitRunner.class)` vira `@ExtendWith(MockitoExtension.class)` e `@RunWith(SpringRunner.class)` sai.
   - Tire o `public` de classes e métodos de teste, que é a convenção do JUnit 5.
3. No `pom.xml`, remova as dependências `junit:junit` e `junit-vintage-engine`. Assim, qualquer import de JUnit 4 que sobrar quebra a compilação em vez de rodar escondido.

Fora do escopo: mudar a lógica de produção e acrescentar casos de teste novos, porque esta tarefa é só a troca de framework. Os testes precisam cobrir exatamente o que cobriam antes.
